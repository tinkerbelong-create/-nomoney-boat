# ノーマネー予想対戦（ボートレース）

実際のボートレースの結果を使って、現金ではなく**ポイント**で友達と収支を競うサイトです。
換金性は一切ありません。実際の舟券を買う機能も、購入サイトへのリンクもありません。

> **公開して友達と遊びたい場合は [DEPLOY.md](./DEPLOY.md) を読んでください。**
> GitHub・Supabase・Vercel の無料枠だけで、0円で公開できます。
> この README は開発者向けの技術的な説明です。

---

## これは何ができるのか

- **メールアドレス＋パスワード**でアカウント登録・ログイン（パスワード再設定つき）
  - 登録後にユーザーID（フレンド検索用）と表示名を決める
- ユーザーIDか表示名でフレンドを検索して申請、相手が承認すると成立
- 登録時に50,000pt。以後、**毎週木曜日に5,000pt**。ポイントのリセットはなし
  - ランキングの「今月」は成績の集計単位であって、残高はリセットされない
- 実際のレースの出走表を見て、**6種類の賭け式**で投票
  - 3連単 / 3連複 / 2連単 / 2連複 / 単勝 / 複勝
  - 拡連複（ワイド）は扱わない方針（`seed.sql` に1行足せば復活可能）
  - 通常買いのほか、ボックス・ながしにも対応
- **投票前にオッズが見える。** 選んだ買い目の倍率と「的中したら何ptになるか」を表示
- 発走時刻で自動締切。以降は変更・取消不可
- レース確定後、**実際の払戻金と同じ倍率**で自動的にポイントが払い戻される
- 収支 / 回収率 / 的中率の3軸でフレンドとランキング（今月・通算）
- タイムラインでフレンドの投票と的中が流れる（締切後のみ表示）
- **的中すると水槽に海の生き物が増える**（全324体）
  - ポイントは使わない。**当てた払戻が高いほど珍しいものが出る**
  - 1000倍以上を1000pt賭けて当てると★10が確定
  - 場の水質・地区・夜のレースで出るものが変わる。24場それぞれに専用の主がいる
  - 生き物は売れない・譲れない・ポイントに戻せない。称号と同じ「記録」

## 全体の構成

```
nomoney-boat/
├─ packages/core/     賭け式・買い目の正規化・払戻計算（Webとワーカーで共有）
├─ apps/web/          Next.js（App Router）。画面と投票。
├─ apps/ingest/       公式サイトからデータを取り込むワーカー。Webとは疎結合。
└─ supabase/          DBスキーマとマスタデータ
```

Webとワーカーは直接やりとりしません。**接点はデータベースだけ**です。
ワーカーが止まってもサイトは見られますし、サイトを作り直してもワーカーは無関係です。

`packages/core` を共有しているのが要点で、
「3連複の `2=1` は `1=2` に直す」というルールをWebとワーカーが**同じコードで**行います。
ここがズレると的中判定が壊れるので、実装をひとつにまとめてテストで守っています。

## セットアップ

### 1. Supabase プロジェクトを作る

[supabase.com](https://supabase.com) で新規プロジェクトを作成します。無料枠で足ります。

作成後、`Project Settings > API` から次の3つを控えます。

| 名前 | 使う場所 |
|---|---|
| Project URL | Web / ワーカー両方 |
| `anon` public key | Web |
| `service_role` key | ワーカーのみ（**絶対にブラウザ側に置かない**） |

### 2. データベースを作る

Supabase の SQL Editor で、次の順に実行します。

1. `supabase/migrations/` の **すべてのファイルを番号順に**（`0001_init.sql` から順に最後まで）
2. `supabase/seed.sql` … 競技マスタ・賭け式6種類・シーズン
3. `supabase/seed_creatures.sql` … **海の生き物324体**（自動生成。手で編集しない）

主なものだけ挙げると:

| ファイル | 内容 |
|---|---|
| `0001_init.sql` | テーブル・RLS・投票関数 |
| `0002_functions.sql` | ランキングや集計の関数 |
| `0003_odds.sql` | オッズのキャッシュ |
| `0009` `0010` | 称号（バッジ） |
| `0012` `0013` | 大会 |
| `0014_points.sql` | **ポイント制度の変更**（入会50,000pt＋毎週木曜5,000pt・リセット廃止） |
| `0016` `0017` | 大会の景品と誓約（**機能は撤去済み。テーブルだけ残っている**） |
| `0018_aquarium.sql` | **水槽。生き物・排出率・グレード表・場の属性** |
| `0019_creature_award.sql` | **生き物の抽選と付与、過去分の遡り** |

`0014_points.sql` が **実行した時点から24か月ぶんのシーズンを自動で作ります。**
それを過ぎる前に先の月を追加してください（[DEPLOY.md](./DEPLOY.md) の「運用中に覚えておくこと」参照）。

### 3. 環境変数を設定する

ルートの `.env.example` をコピーして `.env` を作り、値を埋めます。

```bash
cp .env.example .env
cp apps/web/.env.example apps/web/.env.local
```

`INGEST_USER_AGENT` の連絡先URLは、**必ず自分のものに書き換えてください**。
公式サイトに対して名乗りを上げておくのは最低限の礼儀です。

### 4. 依存関係をインストール

```bash
npm install
```

（npm workspaces を使っているので、ルートで1回叩けば全部入ります）

### 5. まずデータが取れるか確認する

DBに何も書かずに、公式サイトから何が取れるかだけ表示します。

```bash
npm run ingest -- dry-run
```

こんな出力になれば成功です。

```
=== 20260801 の開催 ===
132 レース取得

  桐生 1R  締切 2026/8/1 15:28:00  オールレディース... 1R
  多摩川 1R  締切 2026/8/1 11:32:00  多摩川のおんなカップ 1R
  ...

=== 出走表: 桐生 1R ===
  1号艇 峰 竜太  {"racerId":"4320","racerClass":"A1",...}
  ...

=== 結果: 桐生 1R ===
  1着 1号艇 峰 竜太
  ...
  trifecta  1-2-5   2380pt/100pt  9番人気
```

> **うまく取れないときは**
> 公式サイトのHTML構造が変わった可能性があります。
> `apps/ingest/src/adapters/boatrace.ts` のパース関数を直してください。
> クラス名ではなくテキストの中身を手がかりにしているので、多少の変更では壊れないはずですが、
> 大きなリニューアルがあれば追従が必要です。
> パースに失敗したときは黙って空を返さず必ず警告を出すようにしてあります。

### 6. データを取り込む

```bash
npm run ingest -- schedule    # 開催とレース、締切時刻
npm run ingest -- entrants    # 出走表
```

### 7. サイトを起動する

```bash
npm run dev
```

http://localhost:3000 を開いてメールアドレスを入れると、ログイン用のリンクが届きます。

## 運用（動かし続けるには）

ワーカーを常駐させるだけです。

```bash
npm run ingest -- loop
```

内部でこう回っています。

| 間隔 | やること |
|---|---|
| 1分 | 締切を過ぎたレースの投票を締め切る |
| 5分 | 締切済みで未確定のレースだけ結果を見にいき、確定していれば精算する |
| 60分 | 当日と翌日の開催スケジュール・出走表を更新する |
| 12時間 | 取りこぼした古いレースを回収する |

ただし**常時起動のPCが必要**です。無料で済ませたい場合は次の GitHub Actions 版を使ってください。

### どれくらいリアルタイムか

| | 反映までの時間 |
|---|---|
| **締切（投票できなくなる瞬間）** | **ズレなし。** 発走時刻ちょうど |
| レース結果とポイントの増減 | 公式サイトに結果が出てから最大15分 |
| オッズ | 90秒キャッシュ（見ているレースのみ） |
| 画面の自動更新 | レース一覧30秒、レース詳細20秒 |
| 開催スケジュール・出走表 | 1日2回 |

締切だけは特別扱いで、バッチの実行間隔に一切影響されません。
投票を受け付ける `place_bet` 関数の中でデータベースの時刻と締切時刻を直接比べているので、
仮にワーカーが止まっていても発走時刻を1秒でも過ぎたら投票は弾かれます。

画面は `AutoRefresh` コンポーネントが定期的に取り直します。
タブを裏に回している間は止まり、戻ってきた瞬間に更新するので、
放置していても余計なリクエストを出しません。

### 無料で運用する（GitHub Actions）

常時起動のサーバを借りなくても、GitHub Actions だけで運用できます。
`.github/workflows/` に設定済みです。

| ファイル | 動くタイミング | やること |
|---|---|---|
| `ingest.yml` | **15分ごと** | 締切処理と結果の精算 |
| `daily.yml` | 毎日 6:00 / 12:00 | 開催スケジュール・出走表の取り込み、お題レース決め、取り残しの回収、月間タイトル発行（月初のみ）、毎週木曜のポイント付与 |

**必要な設定**

1. このコードを GitHub リポジトリに push する（**プライベートで構いません**）
2. `Settings > Secrets and variables > Actions` の **Secrets** に2つ登録
   - `SUPABASE_URL`
   - `SUPABASE_SERVICE_ROLE_KEY`
3. 同じ画面の **Variables** に1つ登録
   - `INGEST_USER_AGENT`（例: `NoMoneyBoat/0.1 (+https://自分のサイト/about)`）
4. Actions タブから `daily` を手動実行して、レースが取り込まれるか確認する

**無料枠に収めるための注意**

プライベートリポジトリの Actions 無料枠は月2,000分です。
15分間隔でも1回1〜2分 × 月2,880回で**枠を超えます**。次のどちらかにしてください。

- **リポジトリをパブリックにする** → Actions は完全無料・無制限（おすすめ）
- **開催時間帯だけに絞る** → `ingest.yml` の cron を `*/15 23,0-12 * * *` にする
  （JST 8:00〜21:30 のみ実行。約半分に減る）

> GitHub Actions の定期実行は混雑時にさらに数分遅れることがあります。
> ただし**締切はデータベース側の時刻で判定している**ので、遅れても
> 投票を締め切りそこねることはありません。遅れるのは結果の反映だけです。

**画面に待ち時間を表示しています**

「レースは終わったのにポイントが増えない」と不安にさせないよう、
締切後の画面・投票完了時・タイムラインに
「結果の反映まで最大15分ほどかかります」と出しています。

間隔を変えたときは `NEXT_PUBLIC_SETTLE_DELAY_MIN` を合わせて変更してください
（`apps/web/src/lib/settings.ts`）。

**Webサイト側**は Vercel の無料枠（Hobby）に置けます。
Supabase も無料枠で足ります。合計 **0円** で運用できます。

### 取り残しの回収

何らかの理由で結果を取得できなかったレースは、次のコマンドで回収できます
（`daily.yml` が毎日自動で実行します）。

```bash
npm run ingest -- settle-old
```

結果ページがすでに取得できないほど古い場合は、そのレースの投票を全額返還して決着させます。
ポイントを宙に浮かせたままにしないことを優先しています。

### 自分のPCで動かす場合

```bash
npm run ingest -- loop
```

こちらは1分間隔で動きますが、**PCの蓋を閉じると止まります**。
止まっている間の結果は反映されないので、常用するなら GitHub Actions のほうが確実です。

毎週木曜のポイント付与を手で行う場合はこちらです（`daily.yml` が自動で実行します）。
木曜以外の日に叩いても何も起きません。

```bash
npm run ingest -- weekly
```

**水槽を入れた直後に1回だけ**、過去の的中をさかのぼって生き物を配ります。
そうしないと、これまで当ててきた人の水槽が空っぽのままになります。
何度実行しても、すでに配ったレースは飛ばすので安全です。

```bash
npm run ingest -- backfill-creatures
```

## 公式サイトへのアクセスについて

boatrace.jp の robots.txt は全許可（`Disallow:` が空）ですが、
サイトポリシーは「大量の情報送受信及び大量のアクセス」を禁止しています。
そのため以下を守るように実装してあります。

- **同時接続は1本**。すべてのリクエストが `apps/ingest/src/http.ts` のキューで直列化される
- **1.2秒以上の間隔**を空ける（秒間1リクエスト未満）
- **User-Agent にサービス名と連絡先URLを明記**
- 結果のポーリングは「締切済みかつ未確定」のレースだけに絞る
- 出走表は取得済みのレースを再取得しない
- **5回連続で失敗するとサーキットブレーカが開き、10分間自動停止**する
- 各画面に「データ出典: BOAT RACE オフィシャルウェブサイト」を表示

過去データを大量に取り込みたい場合は、HTMLを叩かず
[公式のファイル配布](https://www.boatrace.jp/owpc/pc/extra/data/download.html)（LZH形式）を使ってください。
そちらが公式の意図に沿った方法です。

## 設計上のポイント

### ポイントは残高を持たず、履歴の積み上げで出す

`point_ledger` に増減だけを記録し、残高は `sum(amount)` で求めます。
残高列を直接更新しないので、「なぜか残高が合わない」が起きません。

二重計上を防ぐ仕掛けはアプリのロジックではなく**DBの制約**に持たせています。

- `point_ledger_signup_uniq` … 入会ボーナス50,000ptは1人1回だけ
- `point_ledger_weekly_uniq` … 木曜の付与バッチが何度走っても、その週のぶんは1回だけ
- `point_ledger_ref_uniq` … 精算バッチを何度実行しても払戻は1回だけ
- `point_ledger_tournament_uniq` … 大会の参加費と払い戻しも1回だけ

バッチは何度でも安全に再実行できます。

### 的中判定に賭け式ごとの分岐がない

投票の買い目も、結果の当たり目も、同じルールで正規化した**文字列**として持っています。
だから的中判定は「文字列が一致するか」だけで済みます。

```
3連単  '1-2-5'   ← 着順どおり
3連複  '1=2=5'   ← 必ず昇順にソート
単勝   '1'
```

複勝のように当たりが複数ある賭け式は、`market_results` に複数行入るだけです。
賭け式が増えてもこの部分のコードは変わりません。

### 締切はサーバ時刻で判定する

端末の時計はずれていることがあります。
締切判定をブラウザ側でやると「一部の人だけ投票できない」という追いにくい不具合になるので、
判定は必ずDBの `now()` で行い、画面のカウントダウンもサーバ時刻を基準に補正しています。

### 締切前はフレンドの投票が見えない

RLSで制御しています。締切前に見えると真似するだけのゲームになってしまうためです。
不要なら `bets_select_friends` ポリシーから締切条件を外してください。

### 将来ほかの競技を足すとき

賭け式は TypeScript の型ではなく `bet_types` テーブルの**行**として持っています。
競技を足すときは行を INSERT してアダプタを1つ書くだけで、
テーブル定義も精算処理も変更不要です。

たとえば競輪には単勝・複勝が存在しませんが、
競輪の `bet_types` に単勝の行を作らなければUIにも出てきません。
競技ごとに賭け式の集合が違っても破綻しない構造にしてあります。

## オッズについて

投票画面で、選んだ買い目のオッズと「的中したら何ptになるか」が出ます。

**取得の仕方が他と違います。** オッズだけは ingest ワーカーではなく、
**誰かがそのレースを開いた瞬間に Web 側が取りに行き、90秒キャッシュ**します。
全レースのオッズを定期取得すると公式サイトへのアクセスが桁違いに増えるためで、
実際に見られたレースのぶんだけで済ませています。締切後は値が変わらないので再取得しません。

扱う6種類すべて、実際の公式ページの構造を確認したうえで実装しています。

| 賭け式 | 通り数 | オッズ |
|---|---|---|
| 3連単 | 120 | ✅ |
| 3連複 | 20 | ✅ |
| 2連単 | 30 | ✅ |
| 2連複 | 15 | ✅ |
| 単勝 | 6 | ✅ |
| 複勝 | 6 | ✅ |

複勝は「1.3-2.3」のような範囲で発表されるため、**低いほうを採用**しています。
期待値を実際より大きく見せないためです。

3連単と3連複のオッズ表は、公式サイトが `rowspan` を使って艇番を省略しているので、
セルの中身ではなく**数値の並び順から買い目を復元**しています。
それぞれ 120通り・20通りが正しく対応づくことを実データでテストしています。

## 注意

このサイトのポイントに換金性はありません。
現金・電子マネー・暗号資産・景品など、金銭的価値のあるものとの交換機能は実装していませんし、
今後も実装しないでください。ユーザー間のポイント譲渡機能も同様です。
譲渡可能にすると、ポイントに財産的価値が生じてしまいます。

本サイトは公営競技の結果を題材にした非営利のファンサイトであり、主催者・施行者とは関係ありません。
